Build Nthuseng Learning Room — AI-Powered Learning Support Platform

Build a modern, responsive AI-powered educational learning-support web application called Nthuseng Learning Room.

1. PURPOSE OF THE APPLICATION

Nthuseng Learning Room is a personalised learning-support platform designed to help an educator/learning-support practitioner understand learners' individual learning needs, create personalised learning plans, generate targeted learning activities, monitor progress, and communicate progress to parents.

The platform should support learners who need additional assistance with foundational literacy and mathematics skills.

The application should NOT present itself as a diagnostic or medical platform. It should support educational decision-making while keeping professional judgement with the educator.

The core workflow is:

Learner Profile → Learning Check → Identify Learning Needs → Personalised Learning Plan → Targeted Learning Activities → Progress Tracking → Parent Progress Report

This must function as ONE integrated platform/dashboard, not as a collection of unrelated AI tools.

Do not use language that makes learners feel labelled or defective.

8. AI LEARNER PROFILE ASSISTANT

Create an AI-powered feature that analyses the information entered in the Learning Check.

The AI should organise the information into:

Suggest which skills should be addressed first based on the information provided.

Generate measurable and age-appropriate learning goals.

IMPORTANT:

The AI must NOT diagnose disabilities, medical conditions, developmental disorders, or psychological conditions.

It should use language such as:

Include a clear message that the educator must review and approve all AI-generated suggestions.

19. AI OUTPUT EXPERIENCE

AI-generated results should never appear as an uneditable block.

Every AI output should have:

20. DEMO DATA

Populate the application with realistic fictional demo learners so that the application looks complete during presentation.

Use fictional names and do not use real learner information.

21. TECHNICAL EXPECTATIONS

Build the application as a functional prototype, not just a static visual mock-up.

Buttons, forms, navigation, AI interfaces, learner profiles, learning plans, activity generation and progress features should behave realistically.

Use reusable components and maintain a consistent design system.

Keep the architecture scalable so that future versions could include a parent portal and learner-facing mobile application.

22. FUTURE VISION

Design the architecture with the possibility of eventually expanding Nthuseng Learning Room into:

Do not attempt to build these future features in the initial MVP unless necessary.

Focus on creating a polished and functional first version.

23. FINAL PRODUCT EXPERIENCE

The application should feel like a real product that could eventually be used by a professional learning-support practitioner.

The core experience should communicate:

Understand the learner → Personalise the support → Create learning activities → Track progress → Communicate with parents.

Prioritise functionality, usability, professional presentation, accessibility, responsible AI and a strong educational purpose.
